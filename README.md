# Marker sequence analysis workflows

This repository contains three lightweight analysis scripts used as reproducibility workflows for targeted marker-sequence analyses. They are intended to document and reproduce the computational procedures used in research projects rather than to serve as standalone software packages.

## Scripts

### `multiplex_amplicon_pipeline.py`

Processes multiple paired-end amplicon libraries, demultiplexes reads using sample-specific primer/index sequences, pools all samples, filters reads against a target reference, orients and dereplicates sequences, performs VSEARCH clustering, and writes mapped reads back to per-sample FASTA files.

Two joining modes are available:

- `concat`: reverse-complement R2 and concatenate it to R1 without requiring overlap.
- `overlap`: merge overlapping pairs with fastp; unmerged pairs are reverse-complemented and concatenated.

The default `--cluster-id 1.0` reproduces exact-sequence clustering used for ribotype discovery in the associated marker analyses. The default fastp minimum overlap is 30 nt.

Example:

```bash
python multiplex_amplicon_pipeline.py \
  --r1-dir R1 \
  --r2-dir R2 \
  --primers primers.tsv \
  --query ITS_reference.fasta \
  --mode concat \
  --cluster-id 1.0 \
  --outdir ITS_run
```

For an overlapping amplicon:

```bash
python multiplex_amplicon_pipeline.py \
  --r1-dir R1 \
  --r2-dir R2 \
  --primers primers.tsv \
  --query 5S_reference.fasta \
  --mode overlap \
  --fastp-min-overlap 30 \
  --cluster-id 1.0 \
  --outdir 5S_run
```

The primer table is tab-delimited and must contain at least five columns in this order:

```text
Library    SampleID    <unused>    ForwardPrimer    ReversePrimer
```

Read names generated by this workflow have the form `<sample_id>.<read_number>`. Sample IDs may contain letters, numbers, underscores, hyphens, or other characters; they are not restricted to a particular taxon or project prefix.

### `haplotype_distribution.py`

Dereplicates a pooled FASTA file, retains haplotypes meeting a global minimum abundance, maps every read to the complete retained haplotype set, and reports per-sample relative abundances.

The default global validity threshold is `--min-size 5`, matching the criterion used in the associated ribotype analyses. Read-to-haplotype mapping identity remains configurable and should be recorded explicitly for each analysis.

By default, the sample ID is extracted from read names using:

```text
^(.+)\.\d+$
```

Thus `Sample_A.123` is assigned to sample `Sample_A`. Other naming schemes can be handled with `--sample-regex`; the first capture group is used as the sample ID.

Example:

```bash
python haplotype_distribution.py pooled_reads.fasta \
  --min-size 5 \
  --identity 0.97 \
  --top 20 \
  --output haplotype_distribution.tsv
```

### `SRA_target_filtering.py`

Extracts mapped target segments from local FASTQ files or directly downloaded SRA runs. Short reads are mapped with BWA-MEM2; long reads are mapped with minimap2.

Supported long-read presets:

- `--long-read-type ont` -> `minimap2 -x map-ont`
- `--long-read-type pacbio-hifi` -> `minimap2 -x map-hifi`
- `--long-read-type pacbio-clr` -> `minimap2 -x map-pb`

For paired-end data, R1 and R2 are now retained independently. The script deduplicates multiple alignments within each input stream, not across mates sharing the same query name. Output IDs are suffixed `/1` and `/2` for paired inputs. This behavior is important when downstream analyses depend on the complete set of target-derived k-mers.

Paired Illumina example:

```bash
python SRA_target_filtering.py \
  --haplotypes combined_ribotypes.fasta \
  --srr SRRXXXXXXXX \
  --paired \
  --mode short \
  --max-reads 1000000 \
  --outdir SRRXXXXXXXX_targets
```

PacBio HiFi example:

```bash
python SRA_target_filtering.py \
  --haplotypes combined_ribotypes.fasta \
  --srr SRRXXXXXXXX \
  --mode long \
  --long-read-type pacbio-hifi \
  --skip-fastp \
  --outdir SRRXXXXXXXX_targets
```

## Python dependencies

Install Python dependencies with:

```bash
python -m pip install -r requirements.txt
```

## External command-line dependencies

Depending on the workflow and selected mode, the following tools are required:

- VSEARCH
- SeqKit
- fastp
- BLAST+ (`blastn`, `makeblastdb`)
- BWA-MEM2
- minimap2
- SAMtools
- seqtk
- NCBI SRA Toolkit (`prefetch`, `fastq-dump`) when `--srr` is used

The scripts check for the tools required by the selected mode before starting the main analysis.

## Reproducibility recommendations

For a publication release, record the exact command line used for every dataset and archive it together with the scripts. Parameters supplied on the command line take precedence over defaults, so the archived commands are the authoritative record of the analysis configuration.

Because `SRA_target_filtering.py` now retains both members of a mapped read pair independently, analyses based on target-read k-mer frequencies should be regenerated when migrating from the earlier global query-name deduplication behavior.
